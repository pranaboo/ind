🔥 EXERCISE 7

.gitignore

This sounds scary but it's easy.

.gitignore tells Git:

> "Don't track these files/folders."



For example, we don't want temporary files.


---

STEP 1 — Create file

Go:

Add file → Create new file

Filename:

.gitignore

Notice the dot at the beginning.


---

STEP 2 — Add rules

Paste:

*.tmp
*.temp
temp/
unnecessary/

Meaning:

Rule	Meaning

*.tmp	Ignore .tmp files
*.temp	Ignore .temp files
temp/	Ignore folder called temp
unnecessary/	Ignore folder called unnecessary



---

STEP 3 — Commit

Commit message:

Add gitignore configuration

Click:

Commit changes


---

STEP 4 — Understand what happens

Suppose your computer has:

test.tmp

Because .gitignore contains:

*.tmp

Git should not treat that file as a normal change to track.


---

STEP 5 — Verify

Open GitHub Desktop.

Create locally:

test.tmp

Then check Changes.

The ignored file should not appear as a normal Git change.

---

Look for:

Revert

> Revert does NOT erase the history. It creates another commit that reverses the unwanted change.

Commit 1
   ↓

   ↓
Commit 3  ← revert of Commit 2

🔥 EXERCISE 11

Merge Conflict

Now comes the scary-looking one.

It's actually simple once you understand the idea.

We need:

main
 │
 ├──── feature-a
 │
 └──── feature-b

Both branches must change the same part of the same file differently.


---

STEP 1 — Start from main

Go to:

student-project

Select:

main


---

STEP 2 — Create feature-a

Create:

feature-a

from main.


---

STEP 3 — Change heading

Open:

index.html

Find:

<h1>My Student Portfolio</h1>

Change it to:

<h1>My Computer Science Portfolio</h1>

Commit:

Update portfolio heading


---

STEP 4 — IMPORTANT

Switch back to:

main

Do not merge feature-a yet.


---

STEP 5 — Create feature-b

From main, create:

feature-b

Now:

main
 │
 ├── feature-a
 │
 └── feature-b

Both branches started from the same original version.


---

STEP 6 — Change the SAME heading differently

On feature-b, open:

index.html

Change:

<h1>My Student Portfolio</h1>

to:

<h1>Welcome to My Portfolio</h1>

Commit:

Change portfolio heading


---

NOW LOOK AT THE SITUATION

feature-a says:

<h1>My Computer Science Portfolio</h1>

feature-b says:

<h1>Welcome to My Portfolio</h1>

Both changed the same original line.

Git can't automatically decide which one you want.


---

STEP 7 — Merge feature-a into main

Switch to:

main

Create a Pull Request:

feature-a → main

Merge it.

Now main contains:

<h1>My Computer Science Portfolio</h1>


---

STEP 8 — Merge feature-b into main

Now create another Pull Request:

feature-b → main

GitHub should detect a conflict.

You'll see something similar to:

> This branch has conflicts that must be resolved.



This is exactly what we wanted.

GitHub prevents a Pull Request from being merged until conflicts are resolved. 


---

STEP 9 — Click Resolve conflicts

Click:

Resolve conflicts

You'll see something similar to:

<<<<<<< main
<h1>My Computer Science Portfolio</h1>
=======
<h1>Welcome to My Portfolio</h1>
>>>>>>> feature-b

Don't panic 😂.


---

What does this mean?

This:

<<<<<<< main

means:

> This is the version currently in main.



This:

=======

means:

> The two versions are separated here.



This:

>>>>>>> feature-b

means:

> This is the version coming from feature-b.




---

STEP 10 — Decide the final version

We can combine both ideas.

Delete the conflict markers and both old versions.

Make the final line:

<h1>Welcome to My Computer Science Portfolio</h1>

So the final file should contain only:

<h1>Welcome to My Computer Science Portfolio</h1>


---

STEP 11 — Mark resolved

Click:

Mark as resolved

Then:

Commit merge


---

STEP 12 — Verify

Go to:

main

Open:

index.html

You should see:

<h1>Welcome to My Computer Science Portfolio</h1>

🎉

You just completed a merge conflict.
